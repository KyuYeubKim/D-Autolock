# D-Autolock

한국 BYD Dolphin 2025 / DiLink 3용 비공식 Android 앱입니다. 선택한 차량 BLE 기기의 RSSI로 접근·이탈을 판단하고 BYD 한국 Cloud의 Sub 계정으로 도어를 제어합니다.

**현재 버전: 휴대폰 0.3.68 / 차량 Bridge 0.3.4 테스트 버전.** 차량 Bridge도 휴대폰처럼 GitHub에서 새 버전을 자동으로 확인·다운로드·설치하도록 했습니다. 0.3.16에서 Bridge 자동 시작, 더 빠른 자동 도어 열림, 미잠금·시동 켜짐 빨간 경고를 추가했습니다. 0.3.7에서 차에서 멀어진 뒤 자동 시동 끄기가 보류되던 문제와 창문 6048 거부를 수정했습니다. 0.3.6에서 메인·설정 화면 캡처를 허용했습니다(로그인 창 제외). 0.3.5에서 메인 화면을 새로 구성했습니다: 상단 상태 바(도어·배터리·시동·창문 아이콘과 새로고침), BLE 신호(우측 상단에서 감도 수정), 차량 제어 6종(출차 준비·하차 마무리·도어 열기·도어 잠금·시동 켜기·시동 끄기), 자동화 스위치, 활동 로그.

## 0.3.68 · 위젯 두 번째 탭 수정, BYD 서버 일시 오류 시 조회 한 번 더, 시동 인증 연결 유지 보완

- **위젯이 명령을 보내지 못하던 문제 수정** — 첫 탭을 처리하는 동안 시스템이 다음 탭을 3초 넘게 붙잡아 두어, 두 번째 탭이 늘 3초 창을 넘겨 도착하고 "다시 누르면 잠금"만 반복됐습니다(0.3.67 위젯은 한 번도 보내지 못함). 이제 각 탭을 바로 끝내 두 번째 탭이 곧바로 전달됩니다.
- **BYD 서버 일시 오류(HTTP 502/503/504)** — 상태 조회가 BYD 서버 쪽 오류로 실패하면 잠깐 뒤 한 번 더 조회합니다. 차량 제어 명령은 다시 보내지 않습니다. 화면 새로고침 실패는 "차량 상태 새로고침 실패 · BYD 서버 일시 오류 (HTTP 502)"로 표시해 도어 명령 실패와 구분합니다.
- **시동 인증 연결 유지** — 키 연결 중 신호 세기가 약하면 끊던 조건을 없앴습니다. 연결 중 신호 세기는 차 안에서도 −88~−90으로 낮게 읽혀, 시동을 거는 사이 몇 초 만에 연결이 끊길 수 있었습니다. 이제 시동 켜짐·멀어짐(연결 끊김·비콘 멀어짐)·다른 명령·2분 경과 때만 끊습니다. 첫 실차 시험에서 블루투스 키로 다시 연 지 3초 만에 시동이 걸렸습니다.

## 0.3.67 · 시동 인증(이미 열린 차도 도어 열기 전송), 홈 화면 위젯

- **시동 인증** — 차가 이미 열려 있으면 '도어 열기'가 "이미 잠금 해제 상태 · 명령 생략"으로 아무것도 보내지 않아, 시동이 안 걸릴 때 공식 BYD 앱으로 문을 다시 열어야 했습니다. 이제 시동이 꺼진 차에서 앱(또는 위젯)의 '도어 열기'를 누르면 이미 열려 있어도 블루투스 키로 다시 열고, 시동을 걸 동안 키 연결을 최대 2분 유지합니다(공식 앱처럼). 시동이 켜지거나(차 블루투스 오디오 연결), 멀어지거나(연결 신호 약함·비콘 멀어짐), 다른 명령이 키를 쓰면 바로 연결을 끊습니다. 자동 열기·주차(P) 열림에는 적용하지 않습니다. 다른 앱이 이미 키 모듈과 연결돼 있으면 보내지 않습니다(그 키가 이미 있음).
- **홈 화면 위젯** — '도어 열기·잠금' 위젯(3×1). 앱의 버튼처럼 한 번 누르면 "다시 누르면 열기/잠금"으로 바뀌고 3초 안에 한 번 더 누르면 보냅니다. 휴대폰 잠금이 풀려 있어야 하고, 결과는 알림으로 알려줍니다. 다른 앱은 위젯을 통해 명령을 보낼 수 없습니다.

## 0.3.66 · 테스트 시간 단축 (앱 동작 변화 없음)

- 테스트용 가짜 BYD 클라우드가 조회·명령마다 실제처럼 1.5초씩 기다리던 것을 10ms로 줄였습니다. 앱 테스트 371개 실행 시간이 약 7분에서 1분 이내로 줄었습니다. 실제 앱은 종전대로 BYD 응답을 1.5초 간격으로 확인합니다.

## 0.3.65 · 시동 끈 직후 오잠금 유예 보강, 주차(P) 열림 판단 수정, 블루투스 키 건너뛰기

- **시동을 끄면 차 블루투스 오디오가 끊기는 순간부터 90초 오잠금 유예** — 지금까지는 BYD 조회로 '시동 꺼짐'을 봐야 유예가 걸렸는데, 운행 중 조회가 한 번도 없으면(공조를 켜지 않은 운행 등) 시동을 끄고 5초 만에 신호 끊김 잠금이 시작됐습니다. 이제 차 오디오(통화·미디어) 연결이 끊기는 순간을 시동 꺼짐으로 보고, 차량 BLE가 가까운 상태에서 끊긴 경우 잠그지 않고 기다립니다. 트렁크 비콘이 8초 넘게 계속 '멀어짐'이면 이미 떠난 것으로 보고 기다리지 않고 잠급니다.
- **주차(P) 자동 열림** — 오래된 차량 정보로 '이미 열림'이라 판단해 건너뛰지 않습니다(달리면 차가 스스로 잠그므로 30초 이내 정보만 믿고, 그보다 오래됐으면 조회 후 판단). 다른 조회 중이면 최대 15초 기다렸다가 다시 시도하고, 그 사이 다시 출발하면 취소합니다. 이미 열려 있던 경우에도 운행 기록(자동 시동 끄기 조건)을 지우지 않습니다.
- **블루투스 키를 쓸 수 없을 때 바로 클라우드로** — 차량 BLE(키 모듈)가 1분 넘게 전혀 안 들리면(멀리 있거나 다른 앱이 키 모듈에 연결 중) 블루투스 키 시도를 건너뛰고 바로 클라우드로 보냅니다(이번 로그에서 약 6초 단축). 원인 확인용으로 그때 휴대폰이 키 모듈과 연결돼 있는지, 연결에 걸린 시간도 기록합니다.

## 0.3.64 · P 상태로 5분 넘게 시동이 켜져 있으면 알림

- **P 상태 시동 켜짐 알림** — 차량 보조 앱이 기어 P를 확인한 뒤 5분이 지나면 BYD 상태를 한 번 조회해, 시동이 아직 켜져 있으면 "P 상태로 5분 넘게 시동이 켜져 있어요" 알림을 띄웁니다(도어 잠김/열림·배터리 %). 차를 두고 내려 휴대폰이 멀어져도 알려줍니다.
  - 그 사이 다른 조회(예: 떠날 때 자동 잠금)에서 시동이 꺼진 게 보이면 추가 조회 없이 끝냅니다. 5분 안에 P에서 빠지면(주행) 세지 않습니다.
  - 같은 주차에는 한 번만 알리고, 나중에 시동이 꺼진 것이 확인되거나 주행하면 알림을 지웁니다.
  - 설정 → 알림 및 백그라운드에서 끌 수 있습니다(기본 켜짐). 휴대폰이 차 안에서 P를 확인한 적이 있어야 합니다(차량 보조 앱 연결 필요).

## 0.3.63 · 시동 끈 뒤 차 옆 신호 끊김 줄이기 · 창문 닫기 생략 · 잠금 결과 다시 확인

- **시동 끈 뒤 차 옆에서 신호가 끊겨 잠기려던 문제 완화** — 시동을 끄면 휴대폰이 꺼진 헤드유닛에 차량 보조 앱 재연결을 약 11초마다 시도하고, 한 번에 6초쯤 블루투스를 붙잡아 차 신호·비콘 수신이 같이 끊기기 쉬웠습니다(최근 로그 3개에서 3~6배). 이제 차 오디오(통화) 블루투스가 끊기면 시동이 꺼진 것으로 보고 45초 간격으로만 시도하고, 다시 연결되면(시동 켜짐) 바로 연결합니다. 운행 시작 때 보조 앱 연결도 빨라집니다.
- **이미 닫힌 창문에는 닫기 명령을 보내지 않음** — 잠근 뒤 조회에서 창문 4개가 모두 닫혀 있으면 생략합니다. 응답 없는 중복 명령 때문에 "창문 닫기 미완료 · 차량에서 직접 확인하세요"가 뜨던 일이 없어집니다. 열림·미확인일 때는 종전처럼 한 번 보냅니다.
- **잠금·열림 결과 다시 조회** — 명령 직후 BYD 조회에 잠금 상태가 비어 있거나 명령 전 측정값이면 3초 간격으로 두 번까지 다시 조회합니다. 명령은 다시 보내지 않습니다.

## 0.3.62 · 시동 끈 직후 잠금 보류 · 블루투스 키 대체 빠르게 · 재열림 방지

- **차가 스스로 다시 잠근 뒤 또 열지 않음** — "이미 열림" 확인 중에 신호가 잠깐 흔들려도 처리 완료로 기록합니다.

## 0.3.58 · 차 앞에서 "열림→잠김→열림" 반복 수정

## 0.3.57 · 자동 업데이트 "서명 불일치" 보류 수정

앱 내 자동 업데이터가 새 버전을 **"앱 패키지·버전·서명이 일치하지 않습니다"로 잘못 보류**하던 버그를 고쳤습니다. 원인은 릴리스 APK가 **v2 서명 전용(v1/JAR 없음)** 이라 일부 기기에서 내려받은 APK의 서명을 읽지 못한 것 — **키가 바뀐 적은 없고**(모든 릴리스 동일 키), 수동 설치는 늘 정상이었습니다. 수정: 릴리스를 **v1+v2 두 체계로 서명**(키 동일)하고, 업데이터가 서명을 v2·v1 함께 요청·폴백해 비교합니다(비교는 종전처럼 엄격 — 다른 키는 거부). 0.3.57은 **수동 설치 1회** 필요(설치본과 같은 키라 덮어쓰기로 데이터·블루투스 키 보존), 이후부터 자동 업데이트 정상. 0.3.56의 블루투스 키 자동화는 그대로 포함. 전 모듈 354개 테스트, Lint 0.

- **Bridge 자동 시작 강화:** 차량 Bridge의 targetSdk를 34→30으로 낮춰 리부팅 후 백그라운드에서 포그라운드 서비스를 시작할 수 있게 했습니다(Android 12+ 제한 회피). 또 15분 주기 JobScheduler 워치독으로, 차량 OS가 Bridge를 강제 종료해도 다시 살립니다. 부팅·휴대폰 Bluetooth 연결은 즉시 트리거, 워치독은 느린 안전망입니다.

## 0.3.15 · 하차 시 더 빨리 잠금

실차 로그(2026-10-10 저녁)에서 하차 후 잠금이 너무 늦게(약 10 m 이상, 신호가 완전히 끊긴 뒤) 됐습니다. 원인 2가지:
- **잠금 backoff 회귀 제거:** 0.3.14에 넣은 자동 잠금 backoff가, 차 안에 있던 동안 쌓인 대기(최대 2분)를 **실제 하차 잠금에도 적용**해 잠금을 지연시켰습니다(로그: 잠금 준비 후 약 37초 지연). 잠금에는 backoff를 적용하지 않도록 되돌렸습니다(자동 열기 backoff는 유지).
- **이탈(잠금) 기준을 −80으로:** 기존 −85는 신호가 거의 완전히 끊겨야 도달해, 사실상 신호 끊김(최대 범위)에서만 잠겼습니다. 추천/기본값을 접근 −75 / 이탈 −80으로 바꾸고, 접근·이탈 최소 간격을 8 → 5 dB로 낮춰 더 가까이서 잠글 수 있게 했습니다(반복 방지 대기값으로 깜빡임은 억제).
- 기존에 저장된 감도(−75 / −85 등)는 유지됩니다. 더 가까이서 잠그려면 BLE 카드의 조절 아이콘 → ‘추천값’ → 저장을 누르세요.

## 0.3.14 · 미잠금 경고 오탐 수정

## 0.3.5 · 새 메인 화면

- **상단 상태 바:** 도어 잠김/열림 아이콘과 ‘업데이트 월/일 시:분’(KST), 배터리 %, 시동, 창문 상태를 아이콘으로 표시하고 오른쪽에 새로고침이 있습니다. 누르면 자세한 상태가 열립니다. 오래된 정보는 미확인으로 표시합니다.
- **BLE 신호 상태:** 신호·평균 dBm·게이지 아래에 잠금/열림 기준값을 표시합니다. 오른쪽 위 조절 아이콘으로 거리 감도·대기 시간을 수정합니다. 처음 설치 기본값과 ‘추천값’은 접근 −70 / 이탈 −85 dBm, 접근 1초 / 이탈 5초 / 신호 끊김 10초입니다(이미 저장한 값은 그대로 유지).
- **차량 제어:** 모두 3초 안에 두 번 눌러야 실행합니다.
  - **출차 준비(해제+시동):** P단 확인 후 도어를 열고, 열림이 확인되면 원격 공조로 시동(전원 ON)을 켭니다. 원격 공조는 주행 READY가 아닙니다.
  - **하차 마무리(시동끔+잠금):** P단·주차브레이크 확인 후 시동을 끄고(Stop), 전원 OFF가 확인될 때만 도어를 잠급니다.
  - **도어 열기 / 도어 잠금 / 시동 켜기(원격 공조) / 시동 끄기(Stop)**. 시동 켜기·끄기는 기존 확인 창을 유지합니다.
- **자동화:** 스위치를 끄면 거리 관찰과 자동 열기·잠금·자동 종료·탑승 공조가 모두 중단되고, 앱을 다시 열어도 꺼진 상태를 유지합니다. 켜면 거리 관찰과 자동 도어를 시작합니다.
- **활동 로그:** 최근 활동을 색상·시간과 함께 보여 주며 오른쪽 위 아이콘으로 전체 활동과 상세 진단 로그를 엽니다.

## 0.3.4 · 도어 반복 동작·잠금 누락·하차 시 전원 켜짐 수정

- **차 옆에서 열림/잠김 반복:** 서 있기만 해도 몸·주머니 때문에 신호가 10~20 dB 흔들려 2초 이탈 대기로는 잠금과 해제가 반복됐습니다. 자동 해제 후 2분 동안은 **20초 연속 멀어짐**이 확인되어야 잠그고, 자동 잠금 후 1분 안에 다시 열 때는 **3초 연속 가까움**이 필요합니다. 신호 끊김 잠금(설정한 초)은 그대로 동작합니다.
- **멀어졌는데 자동 잠금 안 됨:** 수신이 5초 이상 끊기면 신호 안정 기록이 초기화되어, 그 뒤 멀어짐 신호가 몇 번만 오고 끊기면 신호 끊김 잠금이 동작하지 않았습니다. 이전에 안정 수신 기록이 한 번이라도 있으면 신호 끊김 잠금을 수행합니다(처음부터 신호가 불안정하면 여전히 잠그지 않음).
- **전원을 끄고 내리는데 시동이 다시 켜짐:** 전원 OFF 직후 이미 열린 차량에서 탑승 감시가 켜져, 내리려고 연 문을 탑승으로 보고 공조를 시작해 차량 전원이 다시 켜졌습니다. 탑승 시 공조 시작은 **이 휴대폰이 실제로 문을 연 경우에만** 감시하고, 최근 5분 안에 전원 ON이 확인됐으면 감시하지 않습니다. 같은 경우 운행 소유권도 새로 만들지 않습니다.

## 0.3.3 / Bridge 0.2.8 · 크래시 수정과 안정성

- **휴대폰: QR 스캔 크래시 수정.** 스캐너 라이브러리의 기본 화면이 앱에 없는 AndroidX를 요구해 스캔 화면을 여는 순간 종료됐습니다. AndroidX 없이 동작하는 자체 스캔 화면으로 바꾸고 카메라 권한을 직접 요청합니다.
- **Bridge: 차량 진단 파일 저장 크래시 수정.** DiLink에 파일 저장 화면이 없으면 다운로드 폴더(Android 10 이상) 또는 앱 폴더에 저장하고, 내용을 화면에도 표시합니다. Bluetooth 설정 화면이 없을 때도 종료하지 않습니다. QR 창 자동 닫기, 백그라운드 실행 권한 오류, 기어 조회 예외도 앱을 멈추지 않게 처리했습니다.
- 휴대폰 앱에서 설정·Bluetooth·설치 화면 등 시스템 화면을 열 수 없을 때 종료하지 않고 안내합니다. 비정상 종료가 생기면 다음 실행 때 원인(예외 종류·위치, Android 종료 사유)을 진단 로그에 남깁니다.
- 차량 안에서 전원 ON·주행 중이라 자동 열기가 보류되면 재확인 간격을 15초에서 30초·1·2·4·5분으로 늘립니다(차량에서 멀어지면 초기화). 실제 로그에서 이 상황에 수십 번 반복 조회가 있었습니다. 자동 잠금은 이 간격의 영향을 받지 않습니다.
- 이미 잠긴 차량에 자동 잠금이 반복되고 BYD가 모든 창문 닫힘을 보고하면 창문 닫기를 다시 보내지 않습니다(BYD가 6042/6048로 거부하던 경우).
- 차량 신호가 오래 없을 때 BLE 재검색 간격을 2분에서 최대 16분까지 늘려 배터리를 아낍니다. 신호를 다시 받으면 원래대로 돌아갑니다.
- BLE 상태 로그를 매초 대신 상태 변화와 15초 간격으로 기록해 진단 로그가 더 긴 기간을 보관합니다.
- Bridge 0.2.8은 0.2.7 위에 설치하면 기존 QR 연결을 유지합니다.

## 설치 및 업데이트

[Releases에서 APK 다운로드](https://github.com/KyuYeubKim/D-Autolock/releases). Android 8.0 이상, 패키지 `com.dautolock.app`입니다. 기존 D-Autolock 위에 설치하면 계정과 블루투스 설정을 유지합니다. 다른 자동 잠금 앱은 동시에 실행하지 마세요.

0.3.0부터 앱을 열 때마다(5분 간격) 공개 GitHub 릴리스를 확인하고 새 APK를 자동 다운로드합니다. 오른쪽 위 **⋮ → 앱 업데이트**를 누르면 바로 확인합니다. 현재 배포 중인 테스트 버전도 업데이트 대상입니다. 파일 크기·SHA-256·패키지·높은 버전 코드·기존 앱과 같은 서명을 확인한 뒤 **Android 설치 화면을 바로 엽니다**. 설치 화면을 취소하면 같은 버전은 자동으로 다시 띄우지 않으며 메뉴에서 다시 열 수 있습니다. Android의 이 앱 설치 허용과 설치 확인은 필요합니다. 설치 화면을 열기 전 관찰을 중지하며, 업데이트한 앱을 다시 열면 저장 설정으로 재개합니다. 확인·다운로드 옵션을 끄거나 수동으로 확인할 수도 있습니다. BYD 계정 정보는 업데이트 서버에 보내지 않습니다.

## 0.3.2 · 충전 상태 표시

- 차량이 충전 중이면 **차량 상태 위에 충전 상태 카드**를 표시합니다: 충전 중, 배터리 잔량(%)과 게이지, 주행 가능 거리(제공 시), 충전 남은 시간, 완료 예상 시각(KST).
- 기존 실시간 상태 조회 응답의 충전 필드를 사용하므로 BYD 요청을 추가하지 않습니다. 충전 상태는 `chargeState`(없으면 `chargingState`) 값 1일 때만 충전 중으로 봅니다. 연결 표시값(15)은 충전 중으로 보지 않습니다.
- 남은 시간은 `fullHour`/`fullMinute`(없으면 `remainingHours`/`remainingMinutes`)를 사용하고, 완료 예상 시각은 차량 측정 시각 + 남은 시간으로 계산해 화면에서 계속 줄어듭니다. 값이 없으면 미확인으로 표시하고, 15분 이상 지난 정보는 숨깁니다.
- 진단 로그의 상태 기록에 충전 상태·남은 분·배터리 값을 추가했습니다. 실제 한국 Dolphin에서 이 필드가 제공되는지는 실차 로그로 확인이 필요합니다.

## 0.3.1 · 자동 종료 안전장치와 공유 차량 모드

- **자동 종료는 실제 P단일 때만** 합니다. 차량 보조 앱(Bridge)의 실시간 P단 2초 연속 확인이 필수이며, Bridge가 없거나 연결이 끊기면 Cloud 주차브레이크 값으로 대신하지 않고 보류합니다. 수동 Stop의 확인 절차는 유지합니다.
- **이 휴대폰의 운행만 종료**합니다. 이 휴대폰이 문을 열었거나(함께 도착해 다른 휴대폰이 먼저 연 전원 OFF 차량 포함), 그 뒤 이 휴대폰에 연결된 Bridge가 주행(P 해제)을 확인한 경우만 해당합니다. 다른 경로로 열린 것이 확인되거나 12시간이 지나거나 앱이 운행 중 재시작되면 종료하지 않습니다.
- 잠금 후 **대기 시간(기본 15초, 설정에서 5~120초)** 동안 알림과 앱에 **종료 취소**를 표시합니다. 기어 변경·주차브레이크 해제·새 명령·자동 제어 해제 시 바로 취소하고, 대기 후 정차·잠금·모든 문 닫힘·실시간 P·이탈을 다시 확인한 뒤 종료합니다.
- **공유 차량 모드**(설정 → 자동 동작 설정): 여러 운전자가 쓰는 휴대폰에서 켜면 자동 잠금·창문 닫기는 유지하고 자동 종료만 하지 않습니다.
- 도어 잠금 시 창문 닫기는 이제 Stop을 기다리지 않고 잠금 직후 요청합니다.
- 남은 한계: 함께 타고 와서 한 사람만 내리고 다른 사람이 차 안에 가만히 남는 경우는 대기 중 취소에 의존합니다. Bridge는 한 휴대폰에만 연결되므로 자동 종료도 그 휴대폰만 수행합니다.

## 0.3.0 · 상태 새로고침, 활동 로그, 두 번 누르기, 바로 업데이트

- **차량 상태** 제목 아래에 마지막으로 차량 상태를 받은 시각을 **한국 시간(KST)**으로 표시합니다. 차량 측정 시각이 1분 이상 늦으면 함께 표시하고, 30초가 지나면 ‘오래된 정보’로 표시합니다.
- 제목 오른쪽 **새로고침 아이콘**으로 언제든 상태를 다시 조회합니다. 조회 중에는 아이콘이 회전합니다. 읽기 전용이며 기존 단일 작업 큐·BYD 대기·조회 간격(성공 후 5초, 실패 후 30초)을 지킵니다. 조회할 수 없으면 이유와 대기 시간을 알려 줍니다.
- **활동 로그**를 차량 제어 아래 메인에 표시합니다. 최근 5건을 완료·실패·보류·알림 색상과 한국 시간·경과 시간으로 보여 주고, 연속된 같은 알림은 횟수로 합칩니다. 활동 전체(최근 30건)와 상세 진단 로그를 바로 열 수 있습니다.
- 실수 방지를 위해 **도어 열기·도어 잠금·Stop·공조 시작은 3초 안에 두 번** 눌러야 실행합니다. 첫 번째 탭에서 버튼이 강조되고 ‘한 번 더 누르세요’가 표시됩니다. Stop·공조의 기존 확인 창은 유지합니다.
- **⋮ → 앱 업데이트**: 한 번 누르면 확인·다운로드·검증 후 Android 설치 화면까지 바로 엽니다. 앱 실행 시 자동 확인도 하루 한 번에서 5분 간격으로 바꿨습니다.
- 휴대폰 앱만 업데이트하며 Bridge 재설치나 QR 재등록은 필요하지 않습니다.

## 0.2.9 · 간단한 메인 화면과 처음 설정 안내

- 오른쪽 위 **⋮ → 설정**에서 차량 보조 앱 연결/QR, 활동 로그, 자동 도어, 자동 동작 설정, 앱 업데이트, BYD AUTO 계정, 차량 블루투스, 알림·진단 로그 관리를 엽니다. Android 뒤로 가기나 왼쪽 위 ‹로 메인으로 돌아옵니다. 메뉴에서 처음 설정 안내도 다시 볼 수 있습니다.
- 메인 상단은 **도어 잠김/열림 · 시동 켜짐/꺼짐 · 창문 열림/닫힘**과 짧은 알림을 표시합니다. 정보가 없거나 오래되면 해당 상태를 미확인으로 표시합니다. 도어 열림은 잠금 해제 상태이며, 시동 켜짐은 전원 ON입니다. 주행 READY를 확정하지 않습니다. 상단을 누르면 전체 알림과 공조·창문·Stop·READY 진단을 확인합니다. 창문은 하나라도 열림이 확인되면 열림으로 표시합니다.
- BLE 게이지와 현재 신호·자동 도어 ON/OFF·관찰 상태·BYD 응답 대기는 항상 표시합니다. 상세 설명과 진단은 **＋ / −**로 펼치고 접습니다. 감도/대기 시간 버튼은 메인에 유지합니다.
- **도어 잠금 해제 → 도어 열기**로 이름을 바꾸고 수동 새로고침 버튼을 없앴습니다. 감도 저장·차량 선택 후 상태를 자동 갱신하며, 앱이 보일 때 상태가 없거나 오래되면 확인합니다. 기존 제어/사전 조회가 최신 상태를 제공하면 중복 조회를 생략합니다. 동일 직렬 Cloud 작업·BYD 대기를 지키며 실패 시 최소 30초 뒤 재검토합니다. 최신 대시보드 조회도 동일한 짧은 유효기간 안에서 자동 해제 사전 검사에 재사용할 수 있습니다.
- 전체 로그 화면은 휴대폰 시간대와 관계없이 **한국 시간(KST, UTC+9), 최신순**입니다. 날짜 변경도 변환하고 최근 활동 로그에도 한국 시간을 사용합니다. 분석용 원본 파일은 기존 UTC·기록순 형식을 유지하며 보기 화면만 변환합니다.
- 첫 설치 시 **권한/배터리 → Sub 계정 → 차량 선택 → BLE 선택 → 수동 동작 확인 → Bridge QR(선택) → 감도·자동 시작**의 7단계로 안내합니다. 단계는 저장되며 나중에 메인의 ‘처음 설정 이어하기’로 재개할 수 있습니다. 초기 안내 완료 전에는 앱 재실행/감도 저장만으로 자동 도어를 시작하지 않습니다. 마지막 ‘설정 완료·자동 도어 시작’을 눌러 시작합니다. 기존 계정·차량·BLE 설정이 있던 사용자는 업데이트 후 이 초기 안내 때문에 자동 동작이 중단되지 않습니다.
- 휴대폰 앱만 업데이트하며 Bridge 재설치나 QR 재등록은 필요하지 않습니다.

## 0.2.8 · 접근 중 사전 조회와 즉시 판단

- **휴대폰 APK만 업데이트**합니다. 기존 계정·감도·대기 시간과 Bridge QR 연결을 유지하며, Bridge 0.2.7을 다시 설치하거나 QR을 재등록할 필요가 없습니다.
- 자동 도어를 켜고 유효한 BLE 광고를 최소 4회 받으면, 평균 신호가 접근 기준보다 8 dBm 약한 구간부터 차량 상태를 미리 읽습니다. 이탈 기준보다 최소 1 dBm 강한 구간에서만 준비합니다. 예: 접근 -65 / 이탈 -80이면 -73 dBm부터 사전 조회, 실제 해제 기준은 기존 -65 dBm과 설정 대기 시간을 그대로 사용합니다.
- 사전 조회는 읽기 전용이며 **15초에 최대 한 번** 시작합니다. 이미 처리한 접근 구간·명령 간격 대기·BYD 요청 제한 중에는 시작하지 않습니다. 기존 Cloud 작업과 같은 직렬 처리기를 사용하므로 중복 로그인이나 동시 요청을 만들지 않습니다. 준비 조회 중 접근 조건이 충족되면 진행 중인 조회 완료 후 바로 재검토합니다.
- **동일한 계정/차량/관찰 설정에서 받은 결과**, 수신 후 **5초 이내**, 차량 측정 시각 **8초 이내**, 속도 0·전원 OFF·모든 도어 닫힘·잠금 상태가 확인된 경우만 자동 해제 사전 검사에 한 번 재사용합니다. 신호가 준비 구간 밖으로 나가거나 끊김, 설정·차량 변경, 자동 제어 전환·관찰 종료, 새 상태 관측 시 이전 결과를 폐기합니다. 오래됐거나 조건이 맞지 않으면 기존처럼 새로 조회합니다. 전송 직전에도 시간과 접근 조건을 재검사합니다.
- **BLE 수신 콜백에서 즉시 자동 판단**합니다. 신호 끊김·이전 작업 완료 대기는 250 ms 주기로 보완하고, 사전 조회가 끝나면 즉시 재검토합니다. 화면·일반 수신 로그는 기존 1초 주기를 유지합니다. Android 절전과 작업 스케줄링에 따라 실제 실행 시점은 늦어질 수 있습니다.
- 사전 조회 재사용은 **자동 잠금 해제에만** 적용합니다. 수동 제어·자동 잠금·Stop의 최신 상태 검사와 기존 제어 조건은 유지합니다. 신호 조건 미충족, 최소 4회 수신, 설정 대기 시간, 명령 중복 방지와 10초 간격도 유지합니다.
- 진단에 `APPROACH_PREFETCH_START/RESULT/DISCARD/ERROR`, `PROXIMITY_READY`, `PREFLIGHT_TIMING`, `CONTROL_TIMING`을 추가했습니다. `source=approach_prefetch` 또는 `fresh_query`로 준비 결과의 사용 여부를, `readyToSendMs`로 조건 충족부터 명령 전송까지의 시간을 확인합니다. 이 값은 실제 잠금장치 작동 시간과는 다릅니다.
- 사전 조회가 접근 조건 충족 전에 끝났다면 기존에 열기 직전 수행하던 조회를 생략합니다. 급하게 접근하거나 차량 응답이 느리면 조회 완료를 기다려야 하므로 일정한 단축 시간이나 즉시 열림을 보장하지 않습니다. 감도·대기 시간을 무조건 줄이지 않고 먼저 같은 설정으로 비교할 수 있습니다.

## 0.2.7 · 차량 보조 앱과 QR 연결

두 APK를 서로 다른 기기에 설치합니다. **D-Autolock-v0.2.7.apk는 휴대폰용**, **D-Autolock-Bridge-v0.2.7.apk는 차량 DiLink용**입니다. 휴대폰의 자동 업데이트는 휴대폰 APK만 선택합니다. 차량 APK는 별도로 설치합니다.

1. 휴대폰과 차량을 **시스템 Bluetooth 설정**에서 페어링합니다. 기존 거리 감지용 BYD BLE 광고 선택과는 별개입니다.
2. 차량에서 **D-Autolock Bridge → 조회·연결 시작**을 누르고 요청된 Bluetooth·차량 조회 권한을 허용합니다. 화면에서 기어 P/R/N/D가 계기판과 일치하는지 확인합니다. API가 없거나 조회가 실패하면 미확인으로 표시합니다.
3. 차량 앱의 **휴대폰 연결 QR 표시**를 누릅니다. 휴대폰 D-Autolock에서는 BYD 차량을 선택한 상태에서 **차량 보조 앱 연결 / QR → 차량 화면의 QR 스캔**을 누릅니다. 카메라는 QR 스캔 때만 사용하며 영상이나 QR을 서버로 보내지 않습니다.
4. 휴대폰에서 **QR을 표시한 차량의 페어링된 Bluetooth 기기**를 선택합니다. 연결키가 암호화 저장되며, 이후 자동 재연결합니다. QR은 선택한 BYD 차량과 연결됩니다. 기어 SDK로 VIN을 직접 읽어 대조하는 기능은 없으므로 다른 차량의 QR을 등록하지 마세요.
5. 휴대폰에 **차량 보조 앱 인증 연결됨 / 기어 P / P단 연속 확인됨**이 표시되는지 확인합니다. 차량 앱에는 **휴대폰 인증 연결 · 상태 전달 중**이 표시됩니다. Bridge에는 BYD 계정을 입력하지 않습니다.
6. 기존 **실제 자동 도어 제어**, **자동 잠금 후 차량 전원 종료**를 켜서 사용합니다. 차량 앱도 실행 중이어야 합니다. 양쪽 앱 재실행 시 저장 설정으로 연결을 시작하며, 강제 종료·재부팅 후에는 앱을 열어야 합니다. DiLink가 백그라운드 앱을 종료하면 연결이 끊길 수 있습니다.

전원 ON에서 자동 종료하는 조건:

- 기존 BLE RSSI로 확인한 최신 이탈 조건, Cloud의 최신 속도 0·모든 문 닫힘·도어 잠김을 확인합니다. RSSI는 사람의 하차나 탑승자 부재를 직접 감지하는 센서가 아닙니다.
- Bridge를 등록하면 **실제 조회 P단을 2초 이상, 최소 3회 연속 확인**해야 합니다. 각 요청은 응답까지 2초 이내, 마지막 조회는 3초 이내여야 합니다. Stop 전송 직전에도 조건을 다시 검사합니다.
- 이 P 정보로 Cloud EPB **미제공**을 보완합니다. Cloud 또는 차량에서 브레이크 **해제**로 확인되면 실행하지 않습니다. Cloud EPB가 잘못된 값이어도 실행하지 않습니다. 기어 R/N/D·불일치·조회 실패, 연결 끊김·오래된 응답도 보류합니다.
- 잠금 확인 → `TURNOFFENGINE` 한 번 → 전원 OFF 재조회 → 창문 닫기 순입니다. Stop 거부·불확실한 응답을 자동 재전송하지 않습니다. 단순 BLE 끊김으로 잠긴 경우에는 Stop을 추가하지 않습니다.
- Bridge를 한 번 등록한 뒤에는 연결이 끊겨도 Cloud EPB만으로 자동 Stop하지 않습니다. 연결을 해제하거나 차량을 바꾸면 해당 차량의 QR을 다시 등록해야 합니다. 수동 Stop도 등록된 Bridge의 최신 P 확인을 적용하며 기존 직접 주차 확인 절차는 유지합니다.

**실차에서 확인할 부분:** DiLink가 일반 앱의 Bluetooth RFCOMM 데이터 연결을 허용하는지, 기어/브레이크 API와 권한이 제공되는지, Cloud 원격 Stop이 이 차량의 전원을 실제로 끄는지입니다. 소프트웨어 테스트는 실차 검증을 대신하지 않습니다. 보조 앱만 설치하면 종료가 보장되는 것은 아닙니다.

### 진단 및 재연결

- 휴대폰 진단 로그에 `VEHICLE_LINK_PAIRED`, `VEHICLE_LINK_SAMPLE`, `VEHICLE_LINK_DISCONNECTED`, `AUTO_STOP_*`가 기록됩니다. 원본 기어값·브레이크값·왕복 시간을 남기며 QR·연결키는 기록하지 않습니다.
- 차량 앱의 **차량 진단 파일 저장**은 현재 SDK 조회 결과·기어 원본값·브레이크 상수·연결 상태를 저장합니다. 브레이크 상수가 제공되지 않으면 임의로 0/1을 해석하지 않고 미제공으로 표시합니다.
- 연결되지 않으면 차량 Bridge 실행, Bluetooth 페어링, 휴대폰에서 선택한 기기를 확인합니다. 음성/오디오 연결만 지원하는 DiLink 환경에서는 데이터 연결이 실패할 수 있습니다. 이 경우 두 앱 진단으로 확인해야 합니다.
- 다른 휴대폰으로 바꾸거나 QR이 노출되었으면 차량 앱에서 **연결 초기화 · 새 QR 만들기** 후 다시 스캔합니다. QR에는 연결키가 있으므로 공유하지 마세요. QR 화면은 60초 뒤 닫힙니다.

### 구현 범위

`:bridge`는 기어·브레이크 getter만 호출하며 시뮬레이션과 차량 setter를 포함하지 않습니다. 제공된 차량 코드의 GET Context 호환 방식은 `BYDAUTO_GEARBOX_GET`에만 제한했습니다. 실제 OS/Binder 권한을 부여하는 기능은 아니며, COMMON 권한과 차량 서비스의 검사가 계속 적용됩니다. 서명 전용 권한을 `adb pm grant`로 받을 수 있다고 가정하지 않습니다.

`:vehiclelink`는 QR 형식, 암호화 저장, HMAC-SHA256 요청·응답 인증, 요청별 난수와 신선도 검사를 공유합니다. Android 보안 RFCOMM 연결 위에서 동작하고, 차량은 최초 인증에 성공한 페어링 휴대폰을 고정합니다. QR 재발급으로 이전 연결을 폐기합니다. 관련 문서: [Android Bluetooth 연결](https://developer.android.com/develop/connectivity/bluetooth/connect-bluetooth-devices), [ZXing Android Embedded](https://github.com/journeyapps/zxing-android-embedded).

- 자동 해제 후 문 열림 조회 간격을 5초로 줄이고, 잠금 후 창문 닫기는 서버가 이미 닫힘을 반환해도 한 번 요청합니다. 도어·창문·공조·종료 결과를 구분합니다.
- **자동 잠금 후 차량 전원 종료**를 추가했습니다. 기본 켜짐이며 창문 처리 후 Stop을 검사합니다. 최신 정차·잠금·문 닫힘·주차브레이크 체결과 종료 기능 지원이 확인돼야 요청합니다. 전원 OFF면 생략하고, ON에서 EPB 미확인이면 보류 사유를 표시합니다.
- 자동 업데이트 확인·다운로드와 Android 설치 화면 연결을 추가했습니다.

### 감도 시작값과 조정

감도 설정은 **동작 기준**이며 휴대폰이 받는 RSSI 세기 자체를 변경하지 않습니다. 예를 들어 접근 기준 −40 dBm에서 평균 신호가 −50 dBm이면 해제 조건이 충족되지 않습니다. 숫자가 덜 음수일수록 강한 신호입니다.

| 목적 | 시작값 | 조정 예시 |
|---|---|---|
| 접근하면 해제 | 평균 ≥ −60 dBm, 1초 | 더 일찍 열려면 −65, 더 가까워야 열리게 하려면 −55 |
| 멀어지면 잠금 | 평균 ≤ −75 dBm, 4초 | 더 일찍 잠기려면 −70, 더 멀어져야 잠기게 하려면 −80 |
| 수신하던 신호가 끊김 | 10초 | 주변 간섭에 의한 짧은 끊김을 피하려면 시간을 늘림 |

이 값은 시작점이며 특정 미터 거리를 보장하지 않습니다. 평소처럼 휴대폰을 소지하고 원하는 위치의 **평균**을 보면서 조정하세요. 두 기준은 최소 8 dBm 간격을 유지하며, 기준 사이에서는 새 열림·잠김 조건이 충족되지 않습니다. 0.2.4에서는 기본 설정으로 저장 후 자동 관찰·제어를 재개합니다. 신호 판단 시간 외에 Cloud 조회·명령 지연이 더해집니다.

### BYD 요청 거부가 반복될 때

1008 기록만으로 세션 만료나 다른 앱과의 충돌을 확정할 수 없습니다. 앱은 계정 정보를 유지하며 대기 후 다음 조회에서 복구를 시도합니다. 관찰과 자동 제어가 꺼져 있으면 대기 종료 후 상태 새로고침으로 조회할 수 있습니다. 대기 중에는 자동 도어 동작이 지연되며, 실제 잠김 여부는 차량에서 확인해야 합니다.

같은 Sub 계정으로 공식 앱이나 다른 기기에도 로그인한다면, 원인 분리를 위해 **공식 앱은 소유자 계정, D-Autolock은 전용 Sub 계정**으로 나누어 테스트하세요. 국내 서버의 동시 로그인 정책은 확인되지 않아 계정 분리만으로 해결을 보장하지 않습니다. 비밀번호·공유 권한이 바뀐 경우에는 저장 계정을 수정해야 합니다.

## 사용 순서

1. 공식 BYD AUTO에서 Sub 계정의 차량 공유를 승인하고 도어·공조·창문 제어 권한을 확인합니다.
2. 앱에서 한국 Sub 계정 ID·로그인 비밀번호·원격 제어 PIN 6자리를 한 번 입력해 저장합니다.
3. 공유 차량을 선택하고, **블루투스 기기 검색 / 선택**에서 실제 신호가 수신되는 차량 **BYD BLE** 기기를 선택합니다. 저장된 일반 차량 오디오 기기만 선택하면 BLE 광고를 받지 못할 수 있습니다. 차량이나 계정을 변경하면 기존 기기 선택을 해제합니다.
4. 기본 켜짐인 **앱 실행·감도 저장 시 자동 제어 시작**으로 관찰과 자동 도어가 시작됩니다. 대시보드의 `수신 N회`가 증가하고 dBm 값이 표시되는지 확인합니다. 자동 시작 옵션이 꺼져 있으면 **거리 관찰 시작**을 누릅니다.
5. **실제 자동 도어 제어**가 켜졌는지 확인합니다. 꺼져 있으면 관찰·로그 기록만 수행합니다. 자동 시작 옵션을 끄면 앱 재실행으로 자동 제어를 켜지 않습니다.
6. 필요한 경우 **탑승 시 공조 시작**을 켭니다. 자동 해제 후 문 열림을 확인하면 시작하며 자동 OFF는 없습니다. **도어 잠금 시 전체 창문 닫기**, **자동 잠금 후 차량 전원 종료**는 기본 켜짐이며 각각 상태 조건을 검사합니다.
7. 알림 권한을 허용하면 도어 결과와 관찰 알림의 제어 버튼을 사용할 수 있습니다. 권한이 없어도 BLE 관찰 자체는 가능합니다.

블루투스 페어링 여부와 BLE 광고 수신은 다릅니다. 전원을 끄면 신호가 사라지는 오디오 기기, BLE 광고가 없는 일반 Bluetooth 기기, 주소가 계속 바뀌는 기기는 근접 해제에 사용할 수 없습니다. **선택한 주소의 실제 광고 수신 여부**를 확인하세요. Bluetooth 디지털 키를 직접 제어하는 방식은 아닙니다. 휴대폰과 차량에 인터넷 연결이 필요합니다.

주변 기기 권한이 필요합니다. Android 8~11은 위치 권한·위치 기능이 필요할 수 있습니다. 화면을 끈 상태에서 관찰하려면 휴대폰 배터리 설정을 제한 없음으로 설정하세요. 앱 강제 종료·재부팅 뒤에는 앱을 다시 열어야 합니다. 자동 시작 옵션이 켜져 있으면 저장 설정으로 관찰·자동 제어를 재개합니다. 휴대폰 부팅만으로 자동 실행하지는 않습니다.

## 자동 판단

| 조건 | 동작 |
|---|---|
| 평균 RSSI ≥ 접근 기준, 접근 대기 시간 및 최소 4회 수신 (기본 -65 dBm·3초) | 잠금 해제 요청 |
| 접근 기록 후 평균 RSSI ≤ 이탈 기준, 이탈 대기 시간 및 최소 4회 수신 (기본 -80 dBm·8초) | 잠금 요청 |
| 안정된 수신 기록 후 설정한 시간 동안 신호 없음 (기본 10초) | 잠금 요청 |
| 시작 직후부터 계속 미수신 / 불안정한 단발 신호 | 잠금하지 않고 원인 표시 |
| API 요청 처리 중 | 조건 유지, 처리 완료 후 재검토 |
| 상태 조회·정차 조건 등에서 명령 전송 전 보류 | 조건이 계속 유효하면 15초 후 재검토 |
| 실제 명령 전송 후 결과 미확인 | 같은 명령 자동 재전송 없음 |

접근·이탈 기준과 시간은 **거리 감도 / 대기 시간**에서 변경합니다. 접근 슬라이더를 왼쪽으로 움직이면 더 약한 신호에서도 해제를 시작하고, 오른쪽으로 움직이면 더 가까워야 해제합니다. 이탈 슬라이더를 왼쪽으로 움직이면 더 멀어져야 잠금을 시작하고, 오른쪽으로 움직이면 더 가까운 곳부터 잠금을 시작합니다. RSSI는 미터 거리나 실내/실외를 보장하지 않습니다. 대시보드 게이지는 -100~ -30 dBm 범위에 실제 평균 신호 점, 초록색 접근 기준선, 주황색 이탈 기준선을 표시합니다. 오래된 수신 값은 점으로 표시하지 않습니다.

실제 도어 명령 사이에는 10초 간격이 있습니다. 잠금 해제는 전원 OFF·속도 0·최신 차량 상태가 필요합니다. 자동 잠금은 모든 도어 닫힘·속도 0과 전원 OFF 또는 전원 ON+주차브레이크 체결이 필요합니다. 0.2.6부터 전원 ON·주차브레이크 미제공일 때에는 **최신 신호로 이탈 조건을 확인한 경우에 한해 도어 잠금**을 요청합니다. 이 조건은 Stop에 적용되지 않습니다. 상태가 없거나 오래되면 실행하지 않고 이유를 기록합니다. **설정 시간은 신호 조건 판단 시간이며 실제 동작까지는 통신·상태 조회 시간이 더 걸립니다.**

휴대폰 Bluetooth가 꺼지거나 검색 오류가 발생한 경우에도 이전의 유효한 수신 기록을 기준으로 신호 끊김 조건을 검사합니다. 사용자가 **거리 관찰 종료**를 누르면 자동 제어도 종료됩니다.

## 탑승 시 공조 시작과 READY 진단

0.2.4까지의 공조 ON → 2초 → OFF 방식에서 사용자가 전원 꺼짐을 관찰해, 0.2.5부터 자동 OFF를 제거했습니다. 공조 작동과 전원 ON은 주행 가능한 READY와 구분합니다.

- **공조 시작**: P단 주차를 확인하고 수동으로 실행합니다. 앱은 최신 속도 0·전원 상태와 공조 기능 지원을 확인합니다. 전원 OFF에서만 EPB 미제공을 허용하고, 전원 ON이면 EPB 체결 값이 필요합니다. EPB 해제·유효하지 않은 값은 두 경우 모두 차단합니다.
- 자동 옵션은 자동 잠금 해제 확인 후 90초 안에 문 닫힘→열림을 관찰하면 동일한 동작을 실행합니다. 신선한 근접 신호와 정차 조건이 필요합니다.
- 한국 공조 규격으로 23°C ON을 한 번 보냅니다. 이후 OFF 또는 반복 ON을 자동 전송하지 않습니다. 차량의 원격 공조 작동 시간 제한은 적용되며 종료는 차량에서 직접 조작하세요.
- 공조 시작 요청이 전송되면 약 2분간 제한된 상태 조회로 공조·전원·OK 표시값을 기록합니다. 시작 응답이 불확실하면 이를 표시하고 조회만 진행합니다. `/control/getStatusNow`가 지원되지 않거나 응답이 실패하면 공조 상태는 미확인으로 남습니다. 공조 응답에 측정 시각이 없으면 이 점을 함께 표시합니다.
- 문 상태는 Cloud에서 조회합니다. 문을 빠르게 열고 닫으면 중간 상태를 놓칠 수 있습니다. **실제 READY/OK는 계기판에서 확인**합니다. 진단은 `okLight` 값을 지원하는지 확인하는 과정도 포함하며, 이 차량에서 값의 의미가 검증됐다는 뜻은 아닙니다.

`powerGear`는 전원 상태이며 P/R/N/D나 실제 READY 확인값이 아닙니다. `CLOSEAIR`는 공조 종료, `TURNOFFENGINE`은 차량 종료입니다. 자동 잠금 후 Stop은 별도로 검사·요청합니다. **0.2.5부터 BLE 끊김만으로 진행된 잠금에는 Stop을 추가하지 않습니다.** Bridge 미등록 환경에서는 전원 ON에서 주차브레이크 체결을 확인할 수 없으면 자동 종료하지 않습니다. 0.2.7의 Bridge 등록 환경에서는 위의 최신 P단 조건을 적용합니다. 수동 Stop에는 최신 정차·전원·주차브레이크 검사가 적용되며, 0.2.6부터 브레이크 정보 미제공에 한해 이번 요청에서 사용자가 직접 확인한 P단·주차브레이크 체결을 사용합니다.

## 잠금과 창문 닫기

수동·자동 잠금 모두 잠김 상태를 확인한 후 `CLOSEWINDOW`를 한 번 보냅니다. 이미 잠긴 상태에서 잠금 버튼을 눌러도 창문 닫기를 요청합니다. 지원 기능 `1026` 및 최신 정차·잠금 상태가 필요합니다. 0.2.4부터는 Cloud가 창문을 모두 닫힘으로 반환해도 한 번 요청하고 결과를 다시 조회합니다.

0.2.6부터 자동 Stop의 조건이 충족되면 Stop을 먼저 처리한 뒤 창문 닫기를 요청합니다. 잠긴 차량의 수동 Stop 후 전원 OFF를 확인했을 때에도 창문 닫기를 한 번 요청합니다. 이는 전원 ON에서 거부된 창문 명령을 무조건 반복하는 방식이 아니며, BYD의 수락 여부는 다시 확인해야 합니다.

잠금과 창문 닫기는 별도 결과로 표시됩니다. 창문 기능·공유 권한·상태 확인이 실패해도 도어 잠금을 실패로 바꾸거나 중복 잠금하지 않습니다. 확인되지 않은 창문 상태를 닫힘으로 표시하지 않습니다.

## 문제가 있을 때 로그 수집

1. 거리 관찰과 자동 도어를 켠 뒤 차량 가까이→멀리→가까이 이동하여 문제를 재현합니다.
2. **진단 로그 보기**에서 최근 기록을 확인하거나 **진단 로그 파일 저장**으로 `.txt` 파일을 저장합니다.
3. 문제 발생 시각과 저장한 파일을 함께 전달합니다. 로그는 자동으로 외부 전송되지 않습니다.

| 기록 | 확인할 내용 |
|---|---|
| `SCAN_START` / `SCAN_STATUS` | 권한, Bluetooth 유형, 배터리 제한, raw/avg RSSI, 수신 횟수·경과 시간, 거리·대기 조건 |
| `SCAN_FAILED` / `SCAN_RESTART` | Android 검색 오류와 복구 시도 |
| `SCAN_WATCHDOG` / `SCAN_RECONFIGURE` | 장시간 미수신 재검색 / 감도 변경 후 새 신호 판단 |
| `MONITOR_SETUP` / `CAPABILITIES` | 로그인·차량 선택·기능 확인 |
| `AUTO_CHECK` / `PREFLIGHT` | 거리 조건 충족 및 실제 차량 속도·전원·EPB·도어·상태 시각 |
| `CONTROL_SEND` / `CONTROL_BLOCK_OR_ERROR` / `READBACK` | 실제 전송, 보류 이유, 결과 재조회 |
| `LOCK_GUARD` / `CONTROL_RECHECK_BLOCK` | EPB 미제공 잠금의 판단 근거 / 전송 직전 조건 변경 |
| `MANUAL_PARKING_CONFIRM` / `STOP_GUARD` | 이번 수동 Stop의 주차 확인 및 미제공 EPB 처리 근거 |
| `WINDOWS_*` | 잠금 후 창문 닫기 결과 |
| `AUTO_OPTIONS` / `AUTO_STOP_*` | 자동 옵션과 잠금 후 전원 종료 시도·결과·보류 이유 |
| `DOOR_STATE_CHANGE` / `NOTIFICATION_ACTION` | 조회에서 확인한 잠금 변경 / 알림 버튼 사용 |
| `ENTRY_*` / `CLIMATE_START_*` | 문 열림 관찰과 공조 사전 검사·ON 요청·응답 (자동 OFF 없음) |
| `READY_WATCH_*` / `READY_OBSERVATION*` | 제한된 진단의 시작·종료·생략, 전원·OK 표시값·측정 시각과 변화 요약 |
| `CLIMATE_OBSERVATION*` | 공조 서버 상태와 측정 시각, 조회 실패 사유 (서버 원문 제외) |
| `PROXIMITY_SETTINGS` | 저장한 감도와 접근·이탈·신호 끊김 대기 시간 |
| `API_OK` / `API_ERROR` | API 종류·응답 지연·오류 설명 |
| `API_BACKOFF` / `ACCOUNT_RECOVERY_1008` | 1008 횟수·다음 요청 대기·제한적 재연결 시도 |
| `CONTROL_SKIP_STATE` | 서버 조회상 이미 요청한 상태여서 제어 명령 생략 |
| `ACCOUNT_RECONNECT` | 저장된 계정의 자동 재연결 시작·성공·실패 (자격 증명 제외) |

로그 시각은 UTC입니다(한국 시각은 +9시간). 현재·이전 2개 파일, 파일당 512 KiB로 약 1.5 MiB 안에서 순환 저장합니다. **저장된 진단 로그 삭제**로 지울 수 있습니다.

## 정보 보관

로그인 ID·비밀번호·세션 토큰·VIN·차량명·제어 PIN 해시는 Android Keystore의 AES-GCM으로 암호화해 보관합니다. 비밀번호는 자동 재연결에 사용하며 로그인 창에는 원문을 채우지 않고 저장 여부만 마스킹해 표시합니다. 제어 PIN 원문은 저장하지 않습니다. BLE 기기 설정은 앱 전용 설정에 저장합니다. 앱 삭제·데이터 초기화·명시적 로그아웃으로 저장 정보가 삭제됩니다.

로그에는 계정 정보, 비밀번호, 토큰, PIN·PIN 해시, VIN, Bluetooth 주소, 서버 원문을 기록하지 않습니다. 진단 로그에는 신호와 동작 시각, 차량의 일부 상태가 포함되므로 공유 전에 내용을 확인할 수 있습니다. Android 백업·기기 이전에서 앱 데이터와 로그를 제외합니다. 광고·분석 SDK는 없습니다.

GitHub 토큰, 원본 APK, 분석 자료, 릴리스 서명 키는 저장소에서 제외합니다. 비밀번호나 제어 PIN을 이슈·채팅으로 보내지 마세요.

## 빌드

JDK 17 또는 21, Android SDK 34와 Gradle Wrapper 8.9를 사용합니다. `local.properties`에 자신의 SDK 경로를 지정합니다.

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. 릴리스는 `.signing/d-autolock.jks`(별칭 `d-autolock`)와 `.signing/release.properties`의 `storePassword`, `keyPassword`를 준비한 후 `assembleRelease`로 빌드합니다. 서명 키를 안전하게 백업해야 기존 앱을 업데이트할 수 있습니다.

테스트는 자동 판단·신호 소실·중복 방지·차량 상태·로그 보관·공조 순서·스위치 및 Android 화면/서비스 회귀를 검증합니다. 실제 차량이나 BYD 계정에는 연결하지 않습니다.
