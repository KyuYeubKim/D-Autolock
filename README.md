# D-Autolock

한국 BYD Dolphin 2025 / DiLink 3 사용자를 위한 **비공식 Android 앱**입니다. 휴대폰에서 선택한 차량 BLE 기기의 신호 세기로 접근·이탈을 판단하고, BYD 한국 Cloud의 로그인된 계정으로 도어를 제어합니다.

**현재 버전은 0.1.0 개인 검증용 프리릴리스입니다. 실제 Dolphin·Sub 계정·백그라운드 BLE 동작은 실차 검증 전입니다.**

## 설치

[GitHub Releases](https://github.com/KyuYeubKim/D-Autolock/releases)에서 `D-Autolock-v0.1.0.apk`를 Android 휴대폰에 내려받아 설치합니다. Android 8.0 이상이 필요합니다. 기존 BydAutoLock과 별도 패키지(`com.dautolock.app`)이므로 함께 설치할 수 있지만, 거리 기반 자동 제어는 한 앱만 켜세요.

## 기능과 현재 범위

| 기능 | 구현 상태 |
|---|---|
| BYD 한국 계정 로그인 | Sub 계정 로그인, 공유 차량 조회·선택, 계정 세션 암호화 저장 |
| 공유 권한 | 서버가 제공한 공유 범위 표시, 차량 기능 조회, 실제 요청마다 BYD 서버 권한 적용 |
| 블루투스 기기 선택 | 저장된 기기 목록 + 주변 BLE 검색, 차량별 사용 기기 선택 |
| 접근 시 Unlock / 이탈 시 Lock | 관찰 모드와 실제 자동 제어 분리, RSSI 안정화·시간 조건 적용 |
| 수동 Lock / Unlock | 지원 기능 및 최신 차량 상태 확인 후 전송, 상태 재조회 |
| Stop | `TURNOFFENGINE` 명령. 정차·EPB·전원 상태와 사용자 주차 확인 후 수동 실행 |
| 문을 열면 주행 READY | **미지원**. 검증된 명령이 없으므로 실행하지 않음 |
| 이탈하면 자동 전원 종료 | **미지원**. 실제 Stop 동작과 주차·탑승자 조건 검증이 필요 |
| 트렁크 제어 | 포함하지 않음 |

`OPENAIR`/`CLOSEAIR` 공조 제어를 시동 또는 종료라고 표시하지 않습니다. `powerGear`는 전원 상태이며 P/R/N/D 변속 위치나 주행 READY 확인값으로 취급하지 않습니다.

## 처음 연결하기

1. 공식 BYD AUTO 앱에서 소유자 계정이 **Sub 계정에 차량 공유와 필요한 제어 권한**을 부여하고, Sub 계정에서 공유를 승인합니다. 이 앱은 계정을 만들거나 공유 권한을 대신 부여하지 않습니다.
2. **Sub 계정 로그인 / 변경**에서 한국 BYD 계정 ID·비밀번호와 해당 계정의 원격 제어 PIN 6자리를 입력합니다. 로그인 비밀번호와 차량 제어 PIN은 서로 다릅니다.
3. **공유 차량 선택**에서 Dolphin을 선택합니다. 차량 목록에 없으면 공식 앱의 공유 승인 상태와 계정 지역을 확인합니다.
4. **블루투스 기기 검색 / 선택**에서 차량의 BLE 기기를 선택하고 주변 기기 권한을 허용합니다. Android 8~11에서는 BLE 검색에 위치 권한과 휴대폰 위치 기능이 필요할 수 있습니다.
5. **거리 관찰 시작**을 누른 뒤 차량 전원 OFF 상태에서도 신호가 계속 표시되는지 확인합니다. 전원을 끄면 사라지는 오디오 Bluetooth 기기, 임의의 주변 기기 또는 주소가 바뀌는 BLE 기기는 이 버전의 자동 도어에 적합하지 않습니다. 고정 주소의 지속적인 BLE 광고가 필요합니다.
6. **차량 상태 새로고침**과 수동 도어 명령을 먼저 확인합니다. 최신 상태, 차량 기능, Sub 계정 권한 및 PIN이 모두 맞아야 합니다.
7. 관찰 화면에서 접근·이탈을 확인하고 **실제 자동 도어 제어**를 켭니다. 화면을 꺼도 관찰하려면 휴대폰 배터리 설정에서 D-Autolock을 제한 없음으로 설정합니다.

계정 비밀번호나 제어 PIN을 GitHub 이슈·채팅·로그에 올리지 마세요. 계정 입력은 휴대폰 앱에서만 합니다.

차량을 변경하면 기존 블루투스 선택을 해제합니다. 새 차량의 기기를 다시 선택해야 합니다.

## 자동 제어 방식

- 기본 접근 기준 -65 dBm, 이탈 기준 -80 dBm. 신호를 평활화한 뒤 접근 3초·이탈 8초 및 최소 4회 샘플을 요구합니다. RSSI는 실제 미터 거리나 차량 실내/실외를 보장하지 않습니다.
- 시작 직후 첫 구간은 기준 상태만 정하며 도어를 제어하지 않습니다. 이후 `멀어짐 → 가까움` 또는 `가까움 → 멀어짐` 전환을 사용합니다.
- 30초 재명령 제한이 있습니다. 제한 중 생긴 전환은 나중에 재실행하지 않습니다.
- 신호가 5초 이상 끊기면 기준 상태를 재설정합니다. **신호 끊김만으로 도어를 잠그지 않습니다.** 따라서 신호가 이탈 구간을 거치지 않고 사라지면 자동 잠금이 발생하지 않을 수 있습니다.
- 전원 OFF, 속도 0, 측정 시각이 30초 이내인 차량 상태가 필요합니다. 잠금은 네 개 도어가 모두 닫힌 상태도 요구합니다. 값이 없거나 해석할 수 없으면 보류합니다.
- 상태 조회 뒤에도 최신 BLE 신호와 현재 설정을 다시 검사합니다. 앱·관찰 종료, 계정·차량·기기 변경 시 대기 중인 자동 명령을 취소합니다. 이미 서버에 전송된 요청은 취소할 수 없습니다.
- 명령은 한 번 전송하고 같은 요청 번호의 결과만 조회합니다. 타임아웃이나 세션 만료 때 제어 명령을 자동 재전송하지 않습니다. 서버 응답과 물리적인 차량 상태 확인을 구분해서 표시합니다.
- 화면을 끈 상태에서는 알림이 있는 foreground service로 관찰합니다. 강제 종료·재부팅 후에는 사용자가 관찰을 다시 시작해야 하며, 자동 제어 스위치는 기본 꺼짐입니다.
- 휴대폰과 차량 모두 인터넷 연결이 필요합니다. Bluetooth 디지털 키 프로토콜을 직접 제어하는 앱은 아닙니다.

## Stop 확인

차량을 P단에 주차한 상태에서 주변과 탑승자를 확인한 후 실행합니다. 앱은 서버 기능 `1031`, 최신 속도 0, 주차브레이크 체결과 전원 상태를 확인하고 `TURNOFFENGINE`을 전송합니다. P단 자체는 API에서 검증되지 않았으므로 사용자 확인을 요구합니다. 계기판의 전원 OFF를 직접 확인하세요. API 거부·상태 미확인은 성공으로 표시하지 않습니다.

## 정보 보관

- 로그인 비밀번호는 저장하지 않습니다.
- 로그인 토큰, VIN, 차량명, 제어 PIN 해시는 Android Keystore의 AES-GCM 키로 암호화하여 앱 전용 저장소에 보관합니다. 제어 PIN 해시는 인증값이므로 평문으로 보관하지 않습니다.
- 선택 기기의 이름·주소와 감도는 앱 전용 설정에 저장합니다.
- 계정·차량 원문 응답, 비밀번호, 토큰, PIN은 로그에 남기지 않습니다. 진단 기록은 최근 30개 동작 설명만 메모리에 유지합니다.
- Android 백업 및 기기 간 데이터 이전에서 앱 데이터를 제외합니다. 광고·분석 SDK가 없으며 BYD 계정 정보는 한국 BYD Cloud 요청에만 사용합니다.
- 이 저장소에는 개발자 GitHub 토큰, 원본 APK, 분석 데이터 및 릴리스 서명 키를 포함하지 않습니다.

## 빌드 및 검증

JDK 17 또는 21, Android SDK Platform 34가 필요합니다. `local.properties`에 자신의 SDK 경로를 지정한 후 실행합니다.

```powershell
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

디버그 APK: `app/build/outputs/apk/debug/app-debug.apk`.

릴리스 APK는 `.signing/d-autolock.jks`와 `.signing/release.properties`에 `storePassword`, `keyPassword`를 준비한 뒤 `assembleRelease`로 빌드합니다. 별칭은 `d-autolock`입니다. 개인 서명 키는 저장소 밖에서 안전하게 백업해야 기존 설치 앱을 계속 업데이트할 수 있습니다. 서명 파일이 없으면 릴리스 빌드는 서명되지 않습니다.

테스트는 접근·이탈 전환, 신호 소실, 변동·재명령 제한, 누락·오래된 차량 상태, 정차·EPB 조건, 서버 결과 판정, 암호화 및 Android 9/14 초기 화면을 검증합니다. 테스트는 BYD 서버나 실제 차량에 명령을 보내지 않습니다.
